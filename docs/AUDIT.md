- **Result: no Critical or High findings.** Nothing was changed in code.
- **Held up (ruled out):**
  - Checklists: the file name is `sha256(sub)` and `sub` comes only from a verified token, so there is no path traversal and no way to name another user's file. PUT is revision-checked under `flock` with a unique temp file and an atomic rename.
  - Auth: every user-data, paid-provider and admin route needs a verified RS256 token (only RS256, `kid` must match an RSA key, issuer/exp/nbf checked, 4 KB cap, unknown-kid refresh at most once a minute). Admin and CMS also need an exact owner id. The token is read from a header, never a cookie, so CSRF does not apply. Routes match exactly on the raw path; trailing or double slashes, case changes and `%xx` give 404.
  - Cache keys: user-influenced keys (`weather-`, `place-`, `web-`, `route-`, `adb-`) cannot collide with `clerk-jwks*` or the OpenSky `token`.
  - Outbound HTTP: every host is fixed in code or private config; user input only goes into URL-encoded path or query parts. Redirects are not followed, TLS is verified, connect timeout 5 s, total 8–20 s. Keys are sent only in server request headers; error messages are fixed text. No SSRF path.
  - IDs in admin paths (enquiry, CMS slug, revision name, media name) are pattern-checked before any file is touched.
  - `.htaccess`: only `api/index.php` and `site.php` run PHP; private code and config sit outside the webroot; no directory listing; HSTS, nosniff, frame options and permissions policy set. The CSP has no inline scripts and uses `object-src 'none'`, `base-uri 'self'` and `frame-ancestors 'self'`.
- **Medium (left for the owner, latent today):**
  - M1 Bright Data daily cap can be overrun (`WebCheck.php:38-43`). The count is read and written without a lock, so concurrent cache misses all pass the check. Bright Data is OFF on the server, so this costs nothing yet. Fix before adding a key: count inside `Store::withLock` (as AeroDataBox does).
  - M2 Sign-in turns off silently if the issuer is missing or malformed (`loadConfig.php:39`, `ClerkAuth.php:25`, `App.php:47-56`). A trailing slash in `clerk_issuer` is enough. Then `/flights`, `/weather`, `/place` and `/web-check` run for anonymous visitors, including paid AeroDataBox look-ups. `/checklist` and `/admin/*` correctly refuse with 503. Live config verified 24 Oct (anonymous 401, `signInRequired: true`). Suggested fix: refuse protected routes when `clerk_issuer` is set but invalid, and fail closed in production unless `FLIGHTDECK_AUTH=off`.
- **Low:**
  - L1 Any signed-in user can use up the shared AeroDataBox allowance (12 calls an hour, 360 units a month) and the Bright Data allowance by varying flight numbers. The caps hold, but everyone loses schedules until the hour or month resets. Sign-up is open. A per-user hourly allowance would contain it.
  - L2 One lock for all AeroDataBox fetches and one for the OpenSky snapshot, each held for up to 15–30 s and waited on with no timeout. A slow provider can tie up PHP workers. The hourly cap and the cooldown limit this.
  - L3 `Checklists::delete()` unlinks `.lock` after releasing it. A PUT waiting on the old lock and a new PUT on a fresh lock file can then both run. This affects only that user's own document.
  - L4 The web-check cache key is `web-<number>-<date>`, but the search also uses `from`/`to`, so the first caller decides the links shown for 15 minutes. These are only search links.
  - L5 `Place` passes the provider's `content_urls` page link to the app unchecked (`Place.php:39`, rendered as `href` in `DestinationPanels.tsx:409`). Wikimedia is trusted, React 19 blocks `javascript:` links and the CSP blocks inline scripts. Restricting it to `https://en.wikivoyage.org/` and `https://en.wikipedia.org/` would close it.
