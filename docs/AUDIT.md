## 9 November 2026: crash found in the live check after the Phase 5 deploy (branch `fix/boundary-and-console-guard`, not pushed)
- **What happened:** after Phase 5 went live (PR #10, `main` at 243247f, Deploy run 42541387673 PASS, smoke 5 passed), the owner's Chrome showed **"Sign-in could not load"** on a flight page. The browser console had one error: `TypeError: Cannot read properties of undefined (reading 'totals')`, inside the owner-console bundle of the *previous* build (`index-AJ3_GHCK.js` with its own `ConsoleShell-DfqEWaHF.js`; both files are from the same build, so this was not old and new files mixed). It appeared at the moment I moved from the console's Usage screen to a flight page. A genuine reload was fine, and repeating the same navigation on the new build did not crash.
- **What it showed, whatever the trigger:** (1) the console stores the `/api/admin/overview` answer and hands it to the Overview, Usage and Costs screens, which read `overview.totals` with no check, so any answer without that shape crashes the **whole app**; (2) the app's catch-all error screen always said "Sign-in could not load" (FE-12 in the baseline), which sent the investigation to the wrong place for several minutes.
- **What is NOT known:** what made that one answer malformed. The live API answered correctly (200, `overview` with 31 totals) before and after. A rate-limit or error body, or a glitch around the deploy, are guesses. I could not reproduce it.
- **Fixes (tests first):** `hasOverview()` (`src/console/guards.ts`) checks the answer before it is stored; a bad answer now shows the console's own "could not load" panel with a retry. The error boundary now says **"Something went wrong"** for an app crash; "Sign-in could not load" is kept only for a real Clerk failure. Four unit tests (`test/crash-guards.test.ts`) and three console checks (C21, a malformed answer as an error object, an empty object, and one without totals). **Mutation check:** with the guard removed, C21 fails with the exact live error text ("reading 'totals'"; the third case shows the same crash one field later); restored, it passes.
- **Verified live after the Phase 5 deploy (before this crash fix):** both retired event names answer 422; `/ads.txt` 404; the contact form is intact; sign-in still enforced; the console overview and Usage load with no NaN; after a genuine reload BA117 for 9 Nov (not yet departed) shows "Departure terminal / Gate not published yet", "not transmitting yet" (correct before departure), weather and Discover. **Not seen:** the "Latest from the web" card on that load (it can be slow or fail on a first try).
- **Results (local, PASS):** `npm run verify` (node 187/187, PHP, build), lint, `docs:check`, `test:ui`, `test:console` (C21 added). CI not yet run.
