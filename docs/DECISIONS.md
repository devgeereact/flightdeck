## ADR-001: preserve current prototype
24 October 2026 · accepted for docs task. Keep React/TypeScript/Express working code unchanged. The new cPanel PHP stack is a target preference, not retrospective proof of implementation. Consequence: PHP parity/migration remains a separate approved code task.

## ADR-002: guest/browser-local V1
Current implementation has no accounts/DB. Treat Clerk/MariaDB as conditional; do not add services solely to match a template. Revisit only if cross-device/persistent shared requirements are accepted.

## ADR-003: honest data provenance
Samples must stay labelled. No guessed boarding/gates/baggage/location. No authorised live flight source currently exists. A schematic is never geographic tracking evidence.

## ADR-004: deliberate releases
Respect the user's limited Actions budget: production-branch/manual deployment is preferred. No repo/workflow exists yet, and documentation does not create one or authorise deployment.

## ADR-005: source backup without Git
Flightdeck has no .git/remote. Approved verified source archive substitutes for bundle for this task; Git history/branches cannot be audited or cleaned. Do not initialise/push as a side effect of docs creation.

## ADR-006: OpenSky replaces FlightAware
24 October 2026 · accepted by the user. FlightAware AeroAPI removed from code and env; OpenSky Network (OAuth2 client credentials) is the live source. Consequence: live mode is callsign-based and position-only. No flight-number/date lookup, scheduled times, gates, baggage, aircraft type or delay; origin/destination unknown; date ignored in live mode. Search maps IATA→ICAO for a partial carrier list. A snapshot is cached 120 s to bound credits. Revisit if schedule/gate data becomes a requirement (needs a second source). Target host chosen: flightdeck.gakinz.com (no DNS/deploy done).

## ADR-008: free live-data stack, personal use
24 October 2026 · accepted by the user (personal, non-commercial use). Google offers no flight API. Live data = OpenSky (position) + adsbdb (usual route, free, not persisted) + AeroDataBox free Basic plan (schedule/gates/baggage; 400 units a month, attribution required, commercial use not allowed). Hard server-side spend limits protect the allowance. Consequences: if Flightdeck ever becomes commercial or public-facing for others, AeroDataBox/AviationStack free plans no longer apply and a paid plan (AeroDataBox Pro, FlightAware Standard) is needed. Node is not extended with this pipeline (PHP is production). No LLM is used to produce flight facts: an AI search can summarise but cannot be an authoritative real-time source and would risk fabricated gates and times.

## ADR-009: Clerk accounts, saved flights in the user's own profile
24 October 2026 · requested by the owner. Clerk application "Flightdeck" (app_3L9GiPD3G6oC1gMh09zhymxZP9b) with a DEVELOPMENT instance only; sign-in by email code or Google, public sign-up. The app uses @clerk/react 6.x (the old clerk-react is deprecated) and only the PUBLISHABLE key, baked into the build as VITE_CLERK_PUBLISHABLE_KEY; no Clerk secret key is used anywhere. Accounts are optional: guests keep working with browser-local saved flights. ## ADR-010: only signed-in users may call the lookup endpoints
24 October 2026 · requested by the owner. The PHP API verifies the Clerk session token on /api/flights and /api/weather (RS256 signature against the instance's PUBLIC key set at <issuer>/.well-known/jwks.json, issuer, expiry, not-before, optional azp). No Clerk secret key is stored. Fails closed (503) if the keys cannot be fetched; cached keys keep working during a short Clerk outage; an unknown key id triggers one rate-limited refresh. The token travels in Authorization and also X-Session-Token because shared hosts can strip Authorization (public/.htaccess also passes it through). /api/config stays public and reports signInRequired. Enforcement turns on when clerk_issuer is set (config.php, CLERK_ISSUER, or derived from the Clerk publishable key in the environment/.env); FLIGHTDECK_AUTH=off disables it for local automated tests only. ROLLOUT ORDER MATTERS: the live server must NOT get clerk_issuer until the app that sends the token is released and Clerk's production domain is verified, otherwise the current live site (no login) is locked out. Then set clerk_issuer to https://clerk.flightdeck.gakinz.com and clerk_authorized_parties to ['https://flightdeck.gakinz.com'] in ~/flightdeck-private/config.php (back it up first) and verify: anonymous 401, signed in 200. The Node reference server is not covered.

## ADR-011: owner console, first-party counters, enquiries
24 October 2026 - requested by the owner. An owner-only console inside the app (#/admin, lazy chunk, shown only when /api/me says isAdmin): Overview, Usage, Costs and limits, Users, Enquiries, Google Analytics, System. Access = a verified Clerk token AND the exact Clerk user id listed in config admin_user_ids; everyone else gets 403 (tested with a real non-owner session). Numbers come from first-party daily aggregate counters (Metrics.php): counts, small top-N maps (airline, route, direction, not-found numbers), provider latency, and a per-day set of salted hashed user ids used ONLY to count distinct users (compacted to a number after two days, files deleted after 400 days). No IP addresses, no cookies, no flight number tied to a person. Anonymous client events (POST /api/event) are a fixed whitelist of counter names. Enquiries (POST /api/contact): honeypot, minimum fill time, size and link limits, 3 per hour per visitor, header-injection-safe email to owner_email (stored regardless of mail success), inbox with new/read/replied/archived. Users view needs the Clerk SECRET key in the server config only (clerk_secret_key); until set it shows a set-up card. GA numbers in the console remain a later phase. Privacy policy must disclose the counters and enquiries before release.
