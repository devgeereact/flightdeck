# Flightdeck

A local React + TypeScript PWA for flight updates, airport-local times, destination weather and travel inspiration.

## Run

```sh
cd /Users/realmrgee/Developer/Projects/flightdeck
pnpm install
pnpm dev
```

Open http://127.0.0.1:5173. The API runs on 127.0.0.1:3001.

## What works now

- Flight number and local departure date search; multiple flight segments supported.
- Clearly labelled samples: BA117 (New York), EK2 (Dubai, delayed), AF1381 (Paris).
- Scheduled/estimated/actual gate times, takeoff and landing, gate/terminal, aircraft, delay and reclaim fields.
- Actual current airport-area weather from Open-Meteo, independently of sample flight data.
- Destination-local clocks, cross-date arrivals, curated tourism links for the three sample destinations.
- Manual refresh, optional 60-second polling while open, visible update history, saved flights stored in the browser.
- Responsive layout, web manifest and production offline shell. API responses are never service-worker cached.

## Real flight data

There is no flight API credential configured. Sample flights are not operational data and never become live by refreshing.

To connect FlightAware AeroAPI:

1. Obtain an AeroAPI subscription/key with suitable endpoint access.
2. Copy `.env.example` to `.env` and set `FLIGHTAWARE_API_KEY` locally. Never commit it or use a `VITE_` variable.
3. Restart `pnpm dev` and select Live flight data.

The server queries `/flights/{ident}`, enriches airports with `/airports/{id}`, filters by origin-local departure date, and caches flight responses for 60 seconds and airports for 24 hours. Requests can incur provider fees. No paid requests are made without a key. Live provider integration is implemented but unverified against a real subscription. Coverage, historical access, future schedules and codeshares depend on the provider. At most the first 20 returned flights are processed; pagination is not yet implemented.

Boarding time and live aircraft position are not provided by this integration and display unavailable. Gate and baggage fields display only when reported. The route drawing is a schematic, not a map of the aircraft's location. Airline links offer a direct way to check source updates for the sample airlines.

Destination ideas are curated for New York, Paris and Dubai, not a worldwide places database or a distance-ranked attraction search. Other airports receive a general tourism search link. Weather describes current airport-area conditions, not conditions at future arrival time.

Open-Meteo's public endpoint is for non-commercial evaluation/prototyping. Before commercial launch, arrange a suitable licence/endpoint. Attribution is displayed in the app. See https://open-meteo.com/en/pricing.

## Validate / production preview

```sh
pnpm test
pnpm build
pnpm start
```

Production runs on http://127.0.0.1:3001, serving both API and built UI. PWA service-worker installation is production-only. The offline shell does not provide live updates, and remote Google Fonts may be unavailable offline (system fonts remain). Install via the browser menu; device-specific installability has not been verified.

This is a local development prototype, not a deployed service. Before public deployment, add production hosting/TLS, authentication where appropriate, shared rate limits, spending limits, persistent server-side cache, richer flight coverage and monitoring. The in-memory per-IP limiter is designed for local use, not distributed production.

## Files

- `src/main.tsx`: React interface and flight refresh flow
- `src/style.css`: responsive visual design
- `src/destinations.ts`: curated destination cards
- `src/types.ts`: shared flight schema
- `server/index.ts`: server-side provider and weather requests
- `server/flight.ts`: validation, normalization and samples
- `server/flight.test.ts`: meaningful validation/normalization tests

No secrets are sent to the browser. Sample flight dates/times are illustrative; airline and airport instructions take precedence.

## VS Code workspace

Open `flightdeck.code-workspace`. Use Terminal → Run Task to select Develop, Build, Test or Production preview. Tasks use mise explicitly so they work even before shell integration loads. Project runtime versions are pinned in `mise.toml`. If mise asks to trust this project, review that file and approve it locally.

The development command starts the API on port 3001 and Vite on 5173. Stop any running production preview before starting Develop, since both use port 3001. See `ROADMAP.md` for remaining work.
